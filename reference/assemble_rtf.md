# Assemble multiple RTF files into one

`assemble_rtf()` concatenates several RTF files generated by
[`generate_rtfreport()`](https://ichirio.github.io/rtfreporter/reference/generate_rtfreport.md)
into a single deliverable. Each input file becomes one or more sections
of the assembled output; the document header (font / colour tables, page
settings) is taken from the **first** input.

## Usage

``` r
assemble_rtf(
  input_files = NULL,
  output_file,
  overwrite = FALSE,
  cover = NULL,
  toc = NULL,
  toc_title = "Table of Contents",
  toc_leader = c("dot", "none"),
  bookmark_prefix = "tfl_",
  book_page = NULL,
  toc_style = getOption("rtfreporter.toc_style")
)
```

## Arguments

- input_files:

  Character vector of paths to RTF files to combine (at least 2). May be
  left out when `toc` is a table (or its path): the table's `file`
  column, in its order.

- output_file:

  Path for the assembled output RTF file: a single string, in a folder
  that exists, and not one of the `input_files`.

- overwrite:

  `TRUE` or `FALSE`; whether to overwrite an existing output file.
  Default `FALSE`.

- cover:

  Optional `list(title, subtitle, date, version, meta)` for a cover
  page. `NULL` (default) = no cover page.

- toc:

  Table-of-Contents specification. `NULL` (default) = no TOC, no
  bookmarks; `"auto"` = auto-extract titles; a character vector = one
  label per input file; a table (column `file`, and optionally `label`,
  `heading`, `level`) or the path of one (`.xlsx` / `.csv`) =
  multi-level layout. See **Table of Contents** above.

- toc_title:

  Bold title rendered on the TOC page, a single string (`""` = an empty
  title line). Named `l`, `c` or `r` as a header cell is, it is aligned
  left, centre or right (`c(l = "Contents")`); unnamed it is centred.
  `"\n"` is a line break in the title, and the tokens of
  [`rtf_text_tokens()`](https://ichirio.github.io/rtfreporter/reference/rtf_text_tokens.md)
  that need no page are filled as in a title: the session's own tokens
  (`options(rtfreporter.tokens = )`), `{DATETIME}`, `{PROGRAM}`. A token
  that is none of them stays as text. The same goes for the text of a
  `heading` of a table `toc`. Default `"Table of Contents"`.

- toc_leader:

  `"dot"` (default) draws a dotted leader between each TOC entry and its
  page number; `"none"` leaves whitespace.

- bookmark_prefix:

  String prepended to every auto-generated bookmark name (default
  `"tfl_"`): letters, digits and `_` only, as a bookmark name allows;
  `""` = none. Helps avoid clashes if you later concatenate multiple
  assembled outputs.

- book_page:

  Text for the compiled document's page number, a single string put into
  every `{BOOK_PAGE}` slot the inputs reserved. `NULL` (default) leaves
  the slots empty.

  Why a slot

  :   A deliverable that will be bound into a book needs two page
      numbers: its own (`Page 1 of 3`) and the book's (`Page 4 of 57`).
      Written from the start they print the same number twice on a
      standalone deliverable, where the two are equal. So the
      deliverable reserves the position instead – `c(c = "{BOOK_PAGE}")`
      in whichever band it wants, header, footer, title or footnote –
      and renders it empty, keeping the row's height. This argument
      supplies the content when the book is built, so filling it cannot
      shift anything.

  What to give

  :   Typically `"Page {AUTO_PAGE} of {AUTO_TOTAL_PAGES}"`. The total
      resolves to the **book's** page count, which is what the
      deliverable could not know on its own. Both follow **Page
      numbering** above: the page is counted from the book's first page,
      a cover and the table of contents included, and the total is all
      of its pages (the first table after a cover and a one-page table
      of contents of a 9-page book reads `Page 3 of 9`).

  Refused

  :   The static `{PAGE}` / `{TOTAL_PAGES}` are rejected: the slot sits
      in one band shared by every page of a section, so a single
      substitution cannot give each page its own number.

- toc_style:

  The size and boldness of the TOC's text: `NULL` (the built-in sizes)
  or a list with the keys `title`, `heading` and `entry`, each
  `list(size = <points>, bold = TRUE/FALSE)`, and `gap`
  (`list(size = )`: the blank line below the title). A list is merged
  over the built-in values key by key, so `list(entry = list(size = 9))`
  changes the entries' size only. Built in: title 14 pt bold, heading 11
  pt bold, entry 10 pt, gap 9 pt. A size is a positive number of points,
  whole or half (`10.5`). `entry` also takes `hanging`: `FALSE`
  (default) writes each entry's wrapped lines at the indent of its first
  line; `TRUE` lines them up where the title starts, after the number
  (see **Table of Contents**), and a positive whole number of twips
  hangs them that far in, the label written whole
  (`list(entry = list(hanging = 360))`). Headings are not affected.
  Default `getOption("rtfreporter.toc_style")`. The font is the
  document's (that of the first input file). Another key, a size that is
  not a positive number, a `bold` that is not `TRUE` / `FALSE` or a
  `hanging` that is not `TRUE` / `FALSE` / a positive whole number is an
  error.

## Value

Invisibly returns `output_file`.

## Details

Page-number fields work correctly across the assembled document provided
the header/footer text uses dynamic tokens:

- `{AUTO_PAGE}` – per-page number rendered by the RTF viewer, counted
  from the assembled file's first page.

- `{AUTO_TOTAL_PAGES}` – the assembled file's total page count, a cover
  and the table of contents included.

See **Page numbering** below.

Static tokens (`{TOTAL_PAGES}`) reflect only the page count of the
individual source file and will be wrong in the assembled output.

## Cover page

Pass `cover = list(...)` to add a cover page section before the TOC.
Recognised fields:

- `title`:

  large centred bold heading (default font size 22 pt).

- `subtitle`:

  medium centred line below the title (14 pt).

- `date`:

  centred line (11 pt).

- `version`:

  centred line (11 pt).

- `meta`:

  character vector of extra centred lines (10 pt).

Any field that is `NULL`, `NA` or empty is skipped, as is an `NA` line
of `meta`. Another field name, or a `cover` that is not a list, is an
error.

## Table of Contents

`toc` can take any of these shapes:

- `NULL` (default):

  no TOC, no bookmarks. Byte-for-byte the pre-v0.0.29 behaviour.

- `"auto"`:

  each input file's title as a level-1 TOC entry. The title is the
  file's title rows (the centred bold rows
  [`rtf_titles()`](https://ichirio.github.io/rtfreporter/reference/rtf_titles.md)
  writes at the top of the body), read as the file shows them and joined
  into one entry with two spaces between them (`"Table 1"` and
  `"Demographics"` give `"Table 1 Demographics"`); a line break inside a
  row (`"\n"`) is joined the same way, never printed as `\line`. A
  table, a figure and a listing are each labelled by their title; a file
  with no title rows takes its running header's `"Table N"` line
  (`"Table 14.1.1 Demographic Characteristics"`: the title written after
  the number on that line, whatever centred lines follow it, a
  population line for one; a line with the number only takes the longest
  other centred line that is not a `<...>` subtitle), and a file with
  neither, its file name without `.rtf`. A file gets one entry however
  many pages it has: a file whose titles change from page to page
  (`"Summary of {PARAM}"` with `page_by`) is labelled by its first
  page's title. Its tokens are filled (`{STUDY}`, `{PAGE}`), except that
  a dynamic page number (`{AUTO_PAGE}`, `{AUTO_TOTAL_PAGES}`) and the
  `{BOOK_PAGE}` slot are left out, and markup keeps its text without its
  formatting.
  [`assemble_folder()`](https://ichirio.github.io/rtfreporter/reference/assemble_folder.md)
  labels its rows the same way.

- a character vector of TOC labels:

  one per input file – same as `"auto"` but with explicit labels.

- a table (`data.frame`):

  one row per file, in order, for multi-level (chapter / table) layouts:
  `file` (the path), and optionally `label` (the entry text; a row with
  no `label`, or an `NA` one, takes its file's title, read as `"auto"`
  reads it), `heading` (a heading printed above the row's entry whenever
  it changes; `NA` = none), `level` (the entry's indent, a whole number
  from 1 to 3, default 2) and `order`.
  [`assemble_folder()`](https://ichirio.github.io/rtfreporter/reference/assemble_folder.md)
  makes one from a folder, ready to edit. `input_files` can then be left
  out: the table's `file` column is used.

- the path of such a table:

  an `.xlsx` or `.csv` file, e.g. the one
  `assemble_folder(spec_file = )` wrote and you edited.

Each TOC entry is an RTF `HYPERLINK` field; clicking it in Word / Pages
jumps to a per-source-file bookmark. Each row also has a `PAGEREF` field
so the page number next to the entry is calculated by the viewer when
the file opens.

The page number stands on a right tab at the right margin. A label too
long for one line wraps before the page-number column, never into it:
each entry has a right indent (`\ri`) of the column's width plus a gap,
six characters at the entry's font size (four digits and two spaces;
more when a page number has more digits), 720 twips (0.5 in) at the
default 10 pt. The page number and its leader stay on the label's last
line, at the margin. Every level has it, with or without a hanging
indent; headings do not. An entry is also kept on one page (`\keep`):
Word never splits it across two TOC pages.

With a hanging indent (`toc_style = list(entry = list(hanging = TRUE))`)
an entry is its number, a tab and its title (`"Table 14.3.2"`, then
`"Summary of ..."`), and the title's wrapped lines start where its first
line does, after the number. The hang is the width of the widest number
in the TOC and a gap of 1 em at the entry's size: a character is 0.6 em
in Courier New (exact) and is taken as 0.75 em in any other font (a
generous estimate: a wrong one leaves a little too much room). Two more
tab stops follow the hang, 2 and 4 em after it, so a number wider than
the hang puts its title at the next of them, never at the page number's
tab. With `"auto"` and
[`assemble_folder()`](https://ichirio.github.io/rtfreporter/reference/assemble_folder.md)
the number is the one the file's title is read with (`"Table 14.1.1"`);
a label given as text is split when it starts with `Table`, `Figure` or
`Listing` and a number (`14.3.2`, `14.3.2.1`, `14.1.1a`). A label that
does not split is written whole, its wrapped lines at the same hang;
when no label splits the hang is 720 twips. A whole number of twips
(`hanging = 360`) is the hang as given, and each label is written whole,
its wrapped lines that far in.

## Page numbering

Every page of the assembled file is numbered in one Arabic sequence from
its first page, and the total is the count of all its pages. The cover,
when there is one, is page 1; the table of contents' pages come next,
then the input files' pages, with no restart anywhere. With a cover, a
one-page table of contents and 7 pages of tables, the pages read 1 of 9
(the cover), 2 of 9 (the table of contents), 3 of 9 (the first table)
... 9 of 9; without the cover, 1 of 8 (the table of contents), 2 of 8
(the first table) ... 8 of 8.

The inputs' `{AUTO_PAGE}` / `{AUTO_TOTAL_PAGES}`, the `book_page` text
and the page numbers the table of contents shows all follow this
sequence. The file is written with the total already in place (every
`NUMPAGES` field's cached value is the count of all pages) and with each
table of contents entry's cached page number, so a viewer that does not
refresh fields shows them too.

## Examples

``` r
# two TFL files in a folder, as a study's output
dir <- file.path(tempdir(), "tfl")
dir.create(dir, showWarnings = FALSE)
for (t in c("14.1.1", "14.2.1")) {
  doc <- rtf_document() |>
    rtf_tables(data.frame(Parameter = "Age", Value = "75.1")) |>
    rtf_titles(list(c(paste("Table", t), "Safety Population")))
  generate_rtfreport(doc, file.path(dir, paste0("t", gsub(".", "_", t,
    fixed = TRUE), ".rtf")), overwrite = TRUE)
}
a <- file.path(dir, "t14_1_1.rtf")
b <- file.path(dir, "t14_2_1.rtf")
out <- tempfile(fileext = ".rtf")

# Plain concatenation (legacy behaviour)
assemble_rtf(c(a, b), out, overwrite = TRUE)

# Auto-TOC: one entry per file, label extracted from each title
assemble_rtf(c(a, b), out, toc = "auto", overwrite = TRUE)

# Multi-level TOC with section headings + cover page (pages 1, 2, 3, 4)
assemble_rtf(
  input_files = c(a, b),
  output_file = out,
  cover = list(
    title    = "Study XYZ-001",
    subtitle = "Final Statistical Report",
    date     = "2026-05-28",
    version  = "v1.0",
    meta     = c("Confidential", "Prepared by ACME Pharma")
  ),
  toc = data.frame(
    file    = c(a, b),
    heading = c("DEMOGRAPHICS", "SAFETY ANALYSES"),
    label   = c("Table 14.1.1 Demographics", "Table 14.2.1 Adverse Events")
  ),
  overwrite = TRUE
)
```
